# 执行、验收、知识与恢复

适用：已审批实施、项目内返修、整体验收、中断恢复与后续补验。工具按实际能力接入；这里规定行为，不提供自动调度服务或强制权限系统。

## Loop 调度

核对批准方案、Graph、阶段授权、项目规则、实际工作区与剩余资源。外层选可恢复活动任务或下一个 READY 任务，内层闭环当前任务：

```text
读取有效审批、范围与资源规则
当本批次还有可执行任务：
  选择可恢复任务或下一个依赖满足的任务
  当当前任务仍可继续：
    核对审批、范围、权限、依赖和剩余限额
    根据当前实际状态实现或执行已允许的修复
    执行当前版本适用的本期必需检查
    保存预期、实际、证据、累计消耗与状态，更新相关文档
    若必需检查通过且证据有效：交接并标记 DONE，退出内层
    分类失败：范围内修复 / 缺少必需条件 / 需要决策 / 停止
    若允许修复：先登记尝试，再实施，返回验证与判定
    否则：保存原因、解除条件和下一动作，退出内层
  若触发批次停止条件：结束当前自动运行
进入整体验收，或交接当前状态与下一入口
```

恢复 VERIFYING / REPAIRING 时先核实现状，选择验证或修复；不要因任务不是 READY 而遗漏，也不盲目重复外部写入。命令、进程与被检查产物应对应当前任务。

### 失败分类和退出

| 原因 | 处理 |
| --- | --- |
| 实现缺陷 | 定位根因，在范围与剩余额度内修复，再验受影响项与必要回归 |
| 测试 / 配置 / 数据错误 | 在授权内修正条件，保留原始失败；不为通过而改掉业务预期 |
| 本期必需环境、能力、权限缺失 | BLOCKED，记录条件、影响和入口，只阻塞相关工作 |
| 业务、范围、架构或验收冲突 | NEED_DECISION，提交问题、影响、建议和受影响部分 |
| 体验偏差 | 按已确认样板和验收修正；新方向或新范围提交复核 |
| 到限、无进展、越权、用户停止 | STOPPED，保存成果与状态 |
| 外部动作结果不明 | 先只读核实，未确认不重放，记录相关 BLOCKED |
| 已批准后续专项暂无条件 | 保持专项未验证，继续本期获授权且独立的工作 |

一次实质修复从允许启动并登记尝试开始，到重验判定结束；启动失败也记录。累计跨会话保留，下一次启动前检查次数限制，已允许的一轮仍受时间、费用、风险限制。外部等待不计代码修复次数。

### 状态

| 状态 | 含义 |
| --- | --- |
| PENDING | 前置任务正常未完成 |
| READY | 依赖满足，审批、授权、能力和必需条件具备 |
| RUNNING | 实现或执行中 |
| VERIFYING | 检查当前成果，等待本次判定 |
| REPAIRING | 已允许在范围和额度内修复，完成后回 VERIFYING |
| DONE | 当前任务本期必需验收通过、证据有效、必要交接可用 |
| BLOCKED | 缺少本期必需条件或结果不明 |
| NEED_DECISION | 业务、范围、验收等判断需要确认 |
| STOPPED | 到限、无进展、越权或明确停止，入口已保存 |

对象、验收标准或覆盖行为改变时，复核历史 DONE 和证据。单任务 DONE 不代表整体验收通过。

## 证据和整体验收

证据关联需求 / Task / 验收、契约版本、被检查源码 / 配置 / 产物或实例、方法、环境、输入、预期、实际、结果、时间与位置。Agent 维护索引并引用现有报告，不要求用户手填。

检查实际执行、条件明确且结果满足预期时才记 PASS。静态审查、构建、Mock、本地、测试服务、真实运行和人工复核分别限定结论。单项构建、结构校验或测试数量不能替代整体验收。未运行记 NOT_RUN，无法验证记 NOT_VERIFIED，实际失败记 FAIL，并保留原因。

整体验收检查：本期需求到成果与检查的覆盖；任务组合后的完整业务路径；接口、页面、数据与配置匹配；关键异常、权限、空状态和旧路径回归；按约定方法判断体验和可接手性；记录实际接收主体、结论与来源。

需要人工接收时，用业务语言列出操作、预期和“通过 / 失败 / 暂时无法验证”的反馈方式，由 Agent 回填。项目约定由其他主体接收时按该约定执行，不虚构接收记录。

**本期完成**：批准范围内必需验收、整体验收、必要材料和约定接收记录齐备，可正式确认“本期研发交付完成”。已批准为后续的真实环境专项保持独立 NOT_VERIFIED 和恢复入口，不抹掉本期结果，也不据此声称真实运行通过。

本期必需检查不可行时，提交替代方法和覆盖差异供确认，不自行降级。等待期限由项目约定；到期保存候选材料、未满足项与恢复条件，结束等待，不自动变成 PASS。独立且仍获授权的任务可继续。

## 文档与知识

需求 / 方案阶段记决定和依据；审批后记版本与批次；实现时更新接口、配置和运行说明；检查时记方法、结果、限制和待验；交付汇总成果、复现入口、接收结论与后续计划。

优先更新已有资料，保留来源、历史条件和新证据影响；区分用户陈述、设计决策、静态实现、实测和未知项。无增量不重复追加，不复制全部日志，不保存密码或密钥。

文档知识更新不等待全部真实环境专项。知识库不可写时保留更新稿、目标位置和待同步状态，必要运行材料须可接手。可选经验提炼 / 外部同步不默认阻止交付，项目明确必需的材料按约处理。

## 中断与后续补验

保存批准版本、状态 / 依赖、实际差异 / 产物、未结束命令、外部结果、证据索引、累计修复与消耗、阻塞 / 决策原因及下一动作。

恢复时核对工作区、版本、进程和外部状态，保护现存未确认改动；按对象变化重验受影响项。保留累计额度，重新计算依赖和范围。记录与实际冲突先核实，不凭上一条总结跳到完成。

多执行者明确唯一记录写入方，或复用已有锁与版本检查。写前重读，避免覆盖并发更新。后续真实结果补入专项、证据和文档；发现缺陷关联原任务并复核受影响结论，保留原检查时间与范围。
