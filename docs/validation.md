## 可复现的工程检查

```bash
python -m unittest discover -s tests -v
python examples/try_delivery.py
```

测试不访问网络、真实账户或业务系统，使用临时项目与虚构批准。

| 检查面 | 代表性边界 |
| --- | --- |
| 接入 | 五 Skill 同包安装、旧单 / 双 Skill 升级、幂等与完整预检、既有规则 / 配置保护、本地修改冲突、路径越界与链接拒绝 |
| 审批与任务 | 草稿不执行、计划 / Graph / 已登记外部契约变化使审批过期、进度更新不使其过期、具体任务与批次授权、路径、依赖环和缺失依赖 |
| 验收与证据 | 无证据不能 DONE、源码 / 报告变化、方法替换、版本绑定、旧证据保留、最新失败覆盖旧 PASS |
| 完成与恢复 | 任务 / 批次 / 整体验收分开、跨批次历史 DONE、最终集成依赖、空必需项不执行、后续专项独立、累计限制和异常恢复入口 |
| 知识与分发 | 空库与未知区分、有界发现、既有正文保护、知识更新不产生安装冲突、被检查文档变化使证据过期、待同步稿交接及包元数据 / 链接 |
| 端到端工具 | 从 inspect / init / check / new 到审批、实际本地检查、交接和源码变更后的证据失效 |

CI 在 Ubuntu / Windows / macOS × Python 3.10 / 3.13 共六种组合执行相同测试，实际结果见 [GitHub Actions](https://github.com/AIVORA988/delivery/actions/workflows/ci.yml)。宿主不允许创建目录符号链接时，仅该用例会按条件跳过，其他路径拒绝测试仍执行。

### 已复现并修复

以下六项定向回归在修复前均实际失败。实现集中于 [delivery.py](../skills/delivery/scripts/delivery.py) 的 guard；回归位于 [test_delivery.py](../tests/test_delivery.py)。不改变 Graph 摘要算法、记录版本或历史文件。

| 问题与源码依据 | 最小复现与影响 | 局部修复 |
| --- | --- | --- |
| 当前 DONE 的时间限额遗漏：done_authorized 未筛选用量，out_of_time 仅影响 next_tasks | max_minutes=60、used_minutes=61，DONE 与全部 PASS 仍 delivery_ready=true；可绕过最终限额 | 当前授权以 within_limits 校验次数与时间；达到时间上限不启动新动作，已完成的 DONE 恰好到限可通过，超限拒绝 |
| 历史 DONE 的时间限额遗漏：历史快照只核 repairs | 首批 T01 用时 61、原上限 60，切换批次后仍认可其 DONE；Feature 依赖也可能采用该结果 | 历史快照同样校验任务全部累计用量，越限不构成有效 DONE 授权，不改写旧快照 |
| 当前限额追溯否定合法历史 DONE：循环对当前 tasks 无差别应用新 repairs 上限 | T01 在原上限 3 次内完成 2 次修复，历史快照有效；当前批次含 T01 / T02 并收紧至 0 次，T02 被 LIMIT_EXCEEDED 阻断 | DONE 可由任一有效同基线批准及其限额证明；恢复活动仍按当前批准检查，不借历史授权继续执行 |
| REPAIRING 未登记尝试：仅校验 repairs 为非负数 | REPAIRING、repairs=0 可执行，包括 max_repairs=0 时，违背先登记修复的规则 | REPAIRING 至少登记一次尝试；最后一次合法修复和 VERIFYING 重验仍允许，超过次数拒绝 |
| 验收定义判定不一致：acceptance_defined 接受任意 CONDITIONAL，而 checks_pass 要求适用必需项 | 只有 NOT_TRIGGERED 条件项时可开始，但永远不能完成；执行与交付门槛冲突 | 两处复用 required_checks；每任务 / Feature / overall 至少一个 REQUIRED 或已触发条件项，保留有其他必需项时 UNKNOWN 可执行但不能完成的语义 |
| 阻断性可选失败可被清除：checks_pass 仅判断当前 verdict 是否为 FAIL | failure_blocks=true 的检查 FAIL，改变源码并只重验必需项后，其旧 FAIL 变 NOT_VERIFIED，整体重新可交付；追加 NOT_RUN 也可绕过 | 保留当前基线中尚未被最新有效 PASS 解除的阻断失败；对象变化或未运行不表示问题已解决，普通 OPTIONAL 行为保持 |

### 保留的设计取舍与未实现能力

- **整体基线**：plan / Graph / 外部设计实质变化后，全局审批与证据过期是现有保守设计；未改为模块级摘要。UNKNOWN 条件判定属于定义变化，须复核，不自动迁移旧 PASS。
- **批次与恢复**：保留 Feature 单选 / 多选、依赖闭合、模块验收先于依赖模块、所选完成 / 批次完成 / 整体完成的区分。历史摘要、未声明 scenario 的计数规则与安装升级保护不变；统一缺陷校验也适用于旧记录，既有超限或不一致数据不会继续放行。
- **操作与实际范围**：operations 的记录结构、非空范围及任务路径可校验；没有逐命令操作模型或实时写入拦截。实际 diff、隐含调用关系与全部测试覆盖仍由 Agent / 复核方检查，不用无关 subjects 冒充业务证据。
- **时间与历史真实性**：每任务限额不是批次总预算；Guard 不自动计时、记录状态迁移历史、认证批准来源或提供防篡改存储。不得降低累计用量或伪造历史快照取得放行。
- **交接与知识**：文件存在和摘要匹配不证明正文正确；新基线 / 成果需核实实际接收仍适用，长期知识保留来源与未验范围。Guard 不自动认证接收主体或推断跨项目知识有效性。

真实宿主多选弹框、支付 / 数据库 / 部署、真实中大型项目跨会话长周期恢复和跨团队契约变更仍需实际项目验证。此次没有新增工作流阶段、Skill、配置、审批层或执行引擎。

## 校验范围

- 安装 CONFIGURED、record_valid、execution_ready、delivery_ready 分别限定含义，不等于全部业务正确。
- 校验器不自动执行业务命令、认证审批身份、自动计时 / 计费、判断所有影响面或提供系统权限隔离。
- 证据摘要只检查被引用文件；远端实例身份和实际业务结果仍需对应证据。
