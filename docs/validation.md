# 验证方法与已知边界

工作流 V1.0，分发包 1.0.0。工程校验与真实项目效果分别记录。

## 可复现的工程检查

```bash
python -m unittest discover -s tests -v
python examples/try_delivery.py
```

测试不访问网络、真实账户或业务系统，使用临时项目与虚构批准。

| 检查面 | 代表性边界 |
| --- | --- |
| 接入 | 五 Skill 同包安装、旧单 / 双 Skill 升级、幂等与完整预检、既有规则 / 配置保护、本地修改冲突、路径越界与链接拒绝 |
| 审批与任务 | 草稿不执行、计划 / Graph / 已登记外部契约变化使审批过期、进度更新不使其过期、具体任务与批次授权、路径、依赖环和缺失依赖 |
| 验收与证据 | 无证据不能 DONE、源码 / 报告变化、方法替换、版本绑定、旧证据保留、最新失败覆盖旧 PASS |
| 完成与恢复 | 任务 / 批次 / 整体验收分开、跨批次历史 DONE、最终集成依赖、空必需项不执行、后续专项独立、累计限制和异常恢复入口 |
| 知识与分发 | 空库与未知区分、有界发现、既有正文保护、知识更新不产生安装冲突、被检查文档变化使证据过期、待同步稿交接及包元数据 / 链接 |
| 端到端工具 | 从 inspect / init / check / new 到审批、实际本地检查、交接和源码变更后的证据失效 |

CI 在 Ubuntu / Windows / macOS × Python 3.10 / 3.13 共六种组合执行相同测试，实际结果见 [GitHub Actions](https://github.com/AIVORA988/delivery/actions/workflows/ci.yml)。宿主不允许创建目录符号链接时，仅该用例会按条件跳过，其他路径拒绝测试仍执行。

## 新入口的校验重点

四个研发入口与独立 Bootstrap 共用记录和执行规则。自动回归覆盖 3/4、15/16、每 Feature 30/31（多个 Feature 总数可超过 30）、单选 / 多选、所选依赖闭合、范围过滤、未审批调用、模块检查先于依赖 Feature、历史 DONE 与累计用量保留、设计 / 归属变更使基线过期，以及 Feature 完成不能替代整体接收。测试中的审批和结果记录是合成夹具，不是业务验收。

以下旧版行为记录按当时版本保留；其中“轻量修复直接执行、两个 Skill”已被本次统一规划审批与五 Skill 入口替代，不作为当前使用规则。

## Agent 行为检查记录

### 2026-11-02：规划与执行入口分离、Feature 选择与子任务闭环

本地 Windows / Python 3.12.14 执行 92 项工程测试，91 项通过，1 项目录符号链接因宿主权限跳过；相比之前新增 20 项回归。`python examples/try_delivery.py` 通过：实际启动两个本地检查进程，未审批草稿不可执行，完成接收后本期通过，源码变化后旧证据失效。五个 Skill 校验器、JSON/YAML、相对文件 / 图片链接与五个本地标题锚点均通过。

独立简单 Bug 样例只给出 `$delivery` 修复请求，未额外指定“只规划”。Agent 实际复现筛选 / 清空不重置页码，7 项修复前检查为 4 PASS / 3 FAIL；生成 simple 方案及一个任务后等待审批，未修改原业务文件或创建拟实施测试。协调者核对原文件摘要不变、审批 PENDING、具体任务 Guard 退出 1 且 execution_ready=false，确认没有沿用旧版低风险直接实施行为。失败仅是修复前复现，不构成已完成修复。

另用独立 Agent 对隔离文字处理工具做前向检查，不提供预期答案：

- 读取用户给定架构与详细设计，实际完成 inspect → init → check → new → guard，形成两个 Feature、三个任务和 contracts 绑定；只规划请求下审批 PENDING、无业务实现或执行证据，Guard 自洽但不可执行。
- 测试协调者实际审阅方案，再写入明确标注的合成审批；执行入口展示 Feature 与依赖并停在选择处，未自行启动。协调者选择 F01、F02 后，Agent 逐 Feature 执行子任务、模块验收和整体候选检查，保留同一方案、Graph、审批与累计用量。
- 实际 14 项应用单元与真实 CLI 子进程测试通过；独立接收前，selection_complete / batch_complete 为 true，delivery_ready 仍为 false。协调者复核代码、原始报告、文档与链接，纠正知识索引的动态待接收措辞、重跑 14 项并追加相应证据，登记合成接收后 delivery_ready=true、issues=[]，基线未改变。
- 原始失败保留：一次测试结果采集因 Windows CRLF 被误判失败，修正采集后重新验证，没有修改业务预期或测试断言；累计一次修复被保留。另发现中文 JSON 输出需按 UTF-8 捕获，已补充进程级编码说明，不修改全局环境。

合成审批与接收仅用于本次隔离测试，不是业务用户审批。原生多选弹框、真实支付 / 数据库 / 部署，以及真实中大型业务的长期跨会话交付未在本轮实测；宿主无多选控件时使用编号列表，Guard 不提供 GUI、调度或运行时权限拦截。

### 2026-11-02：知识构建与研发复用

使用两个独立的本地合成项目，不访问业务系统。评估者只得到 Skill、原始样例和请求，未提供预期结论；后续实施由测试协调者阅读实际方案后明确批准，并单独复核接收。此过程不构成真实业务用户审批或项目验收。

- 存量项目：Bootstrap 按订单模块构建知识，保留原业务和人工文档。它识别到历史“非法数量静默跳过”与当前源码抛错的冲突，区分静态事实和未验证结果，并记录覆盖与继续入口。
- 独立会话复用：delivery 实际读取该索引与订单正文，核对源码及引用摘要，在新优惠需求的方案中采用有效规则并排除过期描述；没有重新运行 Bootstrap 或生成第二份订单正文。
- 新项目：确认默认知识为空后跳过空文档，完成规划并保持审批 PENDING、execution_ready=false；收到测试协调者的实际批准后才实施本地计算器与测试，形成首批知识和索引。
- 执行验证：新项目 12 项、存量项目 15 项本地业务样例测试实际通过。它们只支持各自合成样例的本地结论，不代表真实支付、部署或大型业务项目通过。
- 文档复核：实际走查发现长期正文不宜复制动态接收状态，且本地报告引用需标明访问限制；已据此收紧共享规则，并要求修改被检查文档后追加重验，保留旧报告和批准 plan。
- 独立接收：协调者分别重跑 12 / 15 项测试并复核实现、知识、链接和原批准方案后登记合成样例接收来源；两个项目均由接收前 delivery_ready=false 变为 true，knowledge=UPDATED、issues=[]。文档变化后的重验没有绕过原审批或证据摘要。

自动测试验证安装和记录机制，Agent 走查验证本次实际检索与采用行为；两者都不能证明所有未来任务不会误读或生成错误结论。项目级质量仍须按当前需求、兼容性及实际证据验收。

## 校验范围

- 安装 CONFIGURED、record_valid、execution_ready、delivery_ready 分别限定含义，不等于全部业务正确。
- 校验器不自动执行业务命令、认证审批身份、自动计时 / 计费、判断所有影响面或提供系统权限隔离。
- 证据摘要只检查被引用文件；远端实例身份和实际业务结果仍需对应证据。
